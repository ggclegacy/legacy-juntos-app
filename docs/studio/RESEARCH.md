## Publishing and analytics

- **TikTok:** `video.publish` requires both app approval and creator OAuth authorization. Query creator information and present permitted privacy choices and duration before submitting. Unreviewed clients publish privately. Direct post initialization is limited to 6/min/user; poll publish status. Internal utility use and audit requirements need review before promising approval. Export is the initial supported path. [Get started](https://developers.tiktok.com/doc/content-posting-api-get-started/), [direct post](https://developers.tiktok.com/docs/en/content-posting-api-reference-direct-post), [sharing requirements](https://developers.tiktok.com/docs/en/content-sharing-guidelines).
- **YouTube:** OAuth channel authorization, resumable upload, processing state and private-to-scheduled transition need distinct records. Unverified projects' uploads are private. Current insert documentation says 1 unit in the Video Uploads quota bucket; do not reuse older 1,600-unit assumptions. Analytics reports use OAuth and dimensions/date ranges; retention/watch time are YouTube-specific. [Insert](https://developers.google.com/youtube/v3/docs/videos/insert), [Analytics](https://developers.google.com/youtube/analytics/reference/reports/query).
- **Meta:** Official Pages/Instagram publishing and insights pages were attempted but blocked/429 during this research pass. Treat scope names, Graph API version, personal-professional-profile support, account requirements, media limits and app-review eligibility as **unverified** here. A Facebook professional dashboard does not establish API entitlement. No live Meta adapter is claimed. [Pages posts](https://developers.facebook.com/docs/pages-api/posts/), [Instagram publishing](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/content-publishing), [insights](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/insights/).
- Connector contract: capability and setup state → user OAuth with state/PKCE → server-side encrypted token store → user-approved immutable content version → durable scheduled job → platform receipt → processing/publication record → normalized metric snapshots. Tokens never enter Studio entity JSON. OAuth is not implemented merely by displaying a connection button.
- Metrics: preserve platform, definition, period, observed time and source. Missing values remain missing; no fabricated zeroes, summed snapshot counters, cross-platform “reach” totals or causal performance claims. Manual measurements must be labeled manual. Insights use observed facts; future recommendation learning requires enough data and separately consented provider processing.

## Production workflow decisions

Private originals, separate immutable versions and derivative lineage; task persistence precedes provider submission. Failures before submission may retry with bounded exponential delay. A network timeout after submission is ambiguous: never automatically resubmit a paid generation. Keep `needs_attention` for reconciliation. Persist provider task ID before polling; no fictional percentages. Expired leases without provider IDs require attention. Output download errors resume retrieval, not generation. No cross-provider fallback after potentially accepted requests, or without consent to that provider. Job workers recheck active membership and reference consent.

The product does not guarantee likeness, copyright clearance, music licensing or sponsor compliance. It records user rights assertions, consent and provenance, and requires human review. Private Performance/Prep data stays outside AI and Studio unless the owner deliberately writes/selects an extract; no background ingestion.
