# Creative Studio architecture blueprint

Extend the existing client sanctuary, bearer-authenticated route handlers, Supabase membership, and private/recipient/shared RLS. Preserve old `records` briefs as legacy briefs; no destructive migration. Both people get the same components and server capabilities.

- `studio_entries`: one permission envelope per independent entity, typed as brand, campaign, content, idea, asset, reference, template, deliverable or insight. Foreign keys normalize brand/campaign/parent associations; detailed, validated fields evolve inside JSON. Owner/context/visibility explicit. Identity and audience immutable in V1; choosing Juntos at creation is explicit. Private identity references remain private. Private linked content cannot broaden a brand/campaign audience. Partner comments are separate append-only review records; ownership does not transfer.
- `studio_versions`: immutable binary/text versions, parent-version lineage, original/derivative designation, object path, provenance, provider/model and usage. Object storage, never base64 in DB. Private bucket policies resolve the parent entry audience.
- `studio_jobs`: immutable user-authorized request plus worker-owned lifecycle, task receipt, retry time, lease, attempts, usage and failures. Dedicated worker credential has no browser exposure. Provider output can only become a draft asset version, never a publication or approval.
- `studio_reviews`: version-aware comments/approval/revision requests, visible only through target access. `studio_activity`: actor-only audit history. `studio_social_connections`, `studio_publish_jobs`, `studio_publications`, `studio_metrics`: distinct access-controlled foundations; publishing remains unavailable until real OAuth/worker integrations are installed.
- `CreativeAdapter`: submit/poll contract with outputs in bytes or provider URL; `ModelRouter` filters modality, references, ratio, transparency, quality/latency preference and configured credentials. Exact documented models live in a catalog, not product layout. No model can grant permissions.
- Command center + Create / Campaigns / Calendar / Assets / Brands / Analytics, Apollo always present; supplementary Ideas, Templates and Connections. Reuse emerald/obsidian/gold, Manrope/Cormorant, existing modal and responsive navigation. Intent-first image/video/copy/audio forms, explicit sharing and reference selection.
- Functional planning layer: brands, campaigns, ideas, copy/content, scheduling intentions, reference metadata, sponsorship requirements, reviews, imports of deliberately selected owner-written Performance extracts, template-assisted briefs and export packages. Sample mode remains labeled and never submits paid jobs. Connection and analytics empty states never imply live data.
- Validation: actual PostgreSQL RLS tests, cross-audience relations, malicious mutations, job claiming/recovery, router capability filtering, provider contracts, UI creation/edit/review/calendar/export, full existing lint/build/tests and responsive browser checks.

Deployment is separate from implementation. Apply the Studio migration in staging with private storage; configure providers and worker, then run real account tests before enabling generation. OAuth publishing, provider expansion, automated analytics, semantic embeddings, native timeline editing and direct health-media import remain staged follow-on work unless implemented and tested explicitly.
